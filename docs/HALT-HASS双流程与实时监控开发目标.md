# HALT-HASS 双流程与实时监控开发目标

## 1. 目标

HALT-HASS 工艺固定包含两个 Flojoy 流程：

1. **测试流**：确认所有必需设备已经连接、能够通信并具备测试条件。
2. **循环流**：启动一次，持续采集设备状态和曲线，直到工作台 MQTT 返回测试停止或剩余时长归零。

工单只保存产品大类、客户端测试类型、实验模式、目标板和详细任务执行流程。工单不绑定工艺 ID 或版本。

客户端每次执行未测试或待重做工单时，根据工单的产品大类、客户端测试类型、实验模式和目标板型号选择一个已审核工艺版本。客户端创建测试场次时保存本次选择的工艺版本和完整快照。

工艺和工单均不保存试验时长。工作台曲线文件定义完整试验时长，客户端通过 MQTT 的 `TotalTime`、`RemainTime` 和测试状态显示进度并判断结束。

## 2. 工单执行顺序

正式工单按以下顺序执行：

1. 选择未测试或待重做工单。
2. 客户端提交工单 ID，服务端按工单固化的产品、客户端测试类型、实验模式、电路板组和目标板型号返回已审核工艺版本，操作员选择并下载本次执行版本。
3. 检查 Flojoy 后端和扫码枪。
4. 按所选工艺装配规则扫描目标板和陪测板。
5. 查看安装指导并执行设备通信预检。
6. 运行测试流。
7. 测试流全部通过后，选择工作台曲线，启动 MQTT 测试并运行循环流。
8. 持续保存实时数据，工作台停止后生成并上传逐板报告。

任何必要设备通信失败时，都必须阻止测试流和循环流启动。

## 3. 设备通信预检

工单测试页面提供独立的“设备通信检测”按钮。预检不属于正式工艺节点，不计入工艺测试结果。

IFBOX 必须由 ITECH 3123（48 V）供电后才能通信，预检顺序固定为：

1. 根据本机工作台配置重新解析 ITECH 3123（48 V）当前端口。
2. 连接 3123，并通过 `*IDN?` 确认设备型号和仪器序列号。
3. 设置输出电压为 **48 V**、限流为 **1 A**，然后开启输出。
4. 等待 IFBOX 上电稳定。
5. 以工艺中配置的波特率打开 IFBOX 串口并执行握手。
6. 检查当前工艺使用的其他设备，例如 ITECH 3123（90 V）、脉冲器和存储板。
7. 所有检查通过后，才允许点击“运行测试流”。

预检连接必须在检查完成后关闭，不能占用 Flojoy 正式运行所需的串口或 VISA 资源。预检成功时保留 3123（48 V）输出，让 IFBOX 保持上电；预检失败、退出工单或正式流程启动失败时关闭对应输出。

### 3.1 设备资源职责边界

工艺只保存设备角色、通信协议参数和执行顺序，不保存 `COM`、`ttyUSB`、`ttyACM`、VISA 地址或 MQTT Broker。工作台连接信息由每台客户端独立保存，运行前解析为当前电脑上的实际资源。

| 配置内容 | 保存位置 | 说明 |
| --- | --- | --- |
| 设备角色 | 工艺 | 例如脉冲器、48 V 电源、90 V 电源、IFBOX 和存储板 |
| 波特率和协议参数 | 工艺 | 决定节点如何通信，不决定连接哪一个物理设备 |
| MQTT Broker、端口和 Topic 前缀 | 客户端工作台配置 | 每台移动工作台独立配置 |
| USB VID/PID、USB 序列号、接口标识 | 客户端工作台配置 | 用于串口设备自动识别 |
| 仪器序列号 | 客户端工作台配置 | 用于区分两台同型号 ITECH 3123 |
| 稳定设备路径 | 客户端工作台配置 | Deepin 优先使用 `/dev/serial/by-id`，其次使用 `/dev/serial/by-path` |

首次部署按以下顺序建立绑定：

1. 客户端枚举串口和 VISA 设备。
2. 使用设备型号、USB 身份、接口标识和仪器序列号尝试唯一匹配。
3. 只有一个候选设备时，客户端自动填入绑定依据。
4. 同型号设备无法确定角色时，由操作员手动选择一次，例如指定哪台 3123 用于 48 V、哪台用于 90 V。
5. 操作员保存本机绑定。
6. 后续启动根据已保存身份自动解析当前端口，不依赖设备枚举顺序。

找不到设备、匹配到多个设备或仪器序列号不一致时，预检必须失败并提示重新绑定。不能回退使用工艺中的旧端口。

实现入口包括 `src/services/hass-workbench-config.ts`、`src/services/hass-hardware-binding.ts`、`src/services/flojoy-api.ts` 和 `src-tauri/resources/flojoy/captain/services/halt_hass_preflight.py`。

## 4. 双流程定义

### 4.1 测试流

- 由操作员在工单页面手动启动。
- 检查设备通断和测试条件。
- 任一必要节点失败时，禁止进入循环流。
- 排障后允许重新执行。

### 4.2 循环流

- 测试流成功后只启动一次。
- 流程内部包含循环条件和持续采集节点。
- 客户端不向流程注入工单时长或工艺时长。
- `HALT_HASS_DURATION_LOOP` 仅保留旧工艺节点名称兼容，不计算或决定试验时长。
- 客户端使用 MQTT 返回的 `TotalTime`、`RemainTime` 和测试状态显示进度。
- 正常退出条件是工作台状态变为 `Stopped`，或 MQTT 剩余时长归零。
- 工作台 MQTT 的连接、曲线列表读取、曲线加载、运行和停止由客户端控制，不作为 Flojoy 工艺节点执行。

## 5. 实时数据来源

| 数据 | 来源 | 客户端接入方式 |
| --- | --- | --- |
| 温度、振动的目标值与实际值、工作台状态 | 工作台 HALT-HASS 软件 | Tauri 后台直连 MQTT TCP 1883 |
| 脉冲器曲线 | Flojoy | Flojoy WebSocket |
| IFBOX 通断状态 | Flojoy | Flojoy WebSocket |
| 3123（48 V）、3123（90 V）电压电流 | Flojoy | Flojoy WebSocket |

客户端将不同来源的数据转换为统一的遥测事件，但必须保留数据来源、工单、会话、流程、节点、通道和时间戳。

温度和振动的目标曲线由工作台 HALT-HASS 软件生成和维护，并通过 MQTT 上报。客户端只消费 MQTT 上报的目标值和实际值，不从工艺附件生成目标曲线。

## 6. 图表与数据保存

- 温度目标值与实际值绘制在同一图表内，数据均来自 MQTT。
- 振动目标值与实际值绘制在同一图表内，数据均来自 MQTT。
- 脉冲器目标曲线与实际曲线在同一图表展示，数据来自 Flojoy。
- 设备通断、电压和电流使用状态表展示。
- 图表使用批量刷新和保峰降采样，原始数据不得因显示降采样而丢失。
- 原始数据按会话持续写入本地分片文件，避免长时间运行占满内存。
- 暂存和恢复后继续写入同一会话。

`.stk` 文件只是工艺编辑时保存的附件。系统需要保留原始文件、文件名和哈希，并支持随工艺上传、保存和下载；客户端不解析 `.stk`，不从中生成或渲染曲线，工单运行也不依赖客户端读取该文件。

## 7. 暂存与恢复

- 暂存时向工作台发送 `Pause`，取消 Flojoy 循环流，并保存已采数据和工作台返回的时间状态。
- 恢复时重新检查设备通信并重新执行测试流。
- 测试流通过后向工作台发送 `Continue`，再按工作台返回状态恢复循环流。
- 工作台如果已经是 `Stopped` 或 `Disconnected`，不得自动创建新测试，必须转入异常处理。

## 8. 异常和安全要求

- Flojoy、MQTT 或必要设备断开时，进入告警中止。
- 预检和流程结束后必须释放串口、VISA、MQTT 和 Worker 资源。
- 运行失败不得遗留 Qt 窗口或阻塞 Flojoy Worker。
- 设备凭据和完整硬件标识不得写入普通业务日志。
- 同一工艺在不同 Deepin 工作台运行时，只能使用该客户端保存的设备绑定，不得复用其他工作台的端口。
- 保留现有“暂存后继续”能力。

## 9. 验收标准

- 双流程能够分别编辑、导入、保存、上传和运行，互不覆盖。
- 未通过设备通信预检时不能启动测试流。
- 3123（48 V）按 48 V、1 A 给 IFBOX 供电后，IFBOX 可打开串口才判定可测试。
- 工艺保存后不包含串口、VISA 地址和 MQTT Broker；运行副本能够注入当前客户端解析出的设备资源。
- 两台同型号 ITECH 3123 能够通过仪器序列号绑定为不同角色，重启客户端后仍自动识别。
- 工单详情不包含预先绑定的工艺 ID、版本或工艺时长。
- 客户端查询可执行工艺时只提交工单 ID，不使用前端临时拼装的产品、实验模式或板型号作为权威条件。
- 未测试和待重做工单每次执行前都要求选择工艺版本。
- 客户端拒绝产品、客户端测试类型、实验模式或目标板型号不匹配的工艺。
- 测试场次保存本次实际选择的工艺版本和完整快照。
- 循环流只启动一次，并按工作台 MQTT 状态正常退出。
- 暂存恢复保持同一测试场次和工作台时间状态。
- `.stk` 文件能够随工艺完整保存和下载，文件内容不被客户端解析或修改。
- 温度和振动图表使用 MQTT 上报的目标值与实际值，不使用 `.stk` 生成目标数据。
- 长时间运行时页面可停止、内存不持续线性增长，原始数据完整可追溯。

## 10. 实现状态

### 已完成

- 工单只下发产品大类、客户端测试类型、实验模式、目标板、任务执行流程和默认工作台曲线。
- 可执行工艺接口从工单读取固化路由信息；历史冲突工单无需兼容，可删除后重建，工艺版本不得随之删除。
- 客户端在进入高速率或 SDS 页面前选择匹配的已审核工艺版本。
- 测试场次保存客户端实际选择的工艺版本和完整快照。
- `HALT_HASS_DURATION_LOOP` 不接收时长参数，只保留循环控制和旧工艺节点名称兼容。
- 新增无 Qt、无 PyGraph 的 `READ_PULSER_WAVEFORM` 节点，脉冲器采样结果通过 Flojoy WebSocket 返回客户端。
- 循环流按 Flojoy 服务端真正回到待机状态判定完成，不再以“全部节点曾执行一次”误判完成。
- Tauri 后台已实现工作台 MQTT 直连、Topic 订阅、状态请求、消息事件和退出清理。
- 工单循环页已使用 ECharts 展示：
  - 脉冲器目标曲线与实际曲线；
  - 温度目标值与实际值；
  - 振动目标值与实际值；
  - IFBOX 状态及两台电源的电压、电流。
- MQTT 温度/振动数据只解析工作台实时上报字段，不解析 STK，不生成模拟曲线。
- 页面显示 MQTT 连接参数和连接状态；密码不写入本地缓存和普通日志。
- HALT-HASS 工艺使用 `schemaVersion: 2`，固定保存 `testFlow` 与 `cycleFlow` 两个独立流程，不保留旧单流程兼容分支。
- 工艺编辑器提供测试流、循环流两个独立画布，分别保存节点、连线、观察节点和运行设置。
- 完整工艺导入、导出、暂存、上传和后端读取均保持双流程结构，Flojoy Studio JSON 只导入/导出当前流程。
- 管理端工艺详情提供测试流和循环流两个独立预览页签。
- 工单执行已加入双流程门禁：测试流全部成功后切换到循环流，最终报告合并两个流程的节点结果。
- 工单暂存数据已记录当前流程、测试流是否通过以及两套节点结果。
